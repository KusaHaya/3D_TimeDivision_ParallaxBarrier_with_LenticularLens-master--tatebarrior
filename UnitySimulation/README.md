# 時分割パララックスバリア：Unity光路シミュレーター

固定された斜めの照射像と左右の目を結び、液晶面での到達領域を確認する独立したUnityプロジェクトです。
ProjectPBの描画やArduinoへの送信は変更しません。実機に出力するプログラムではありません。

## 開き方

1. この `UnitySimulation` フォルダーをPCへ保存します。リポジトリから取得する場合は **realsense-ray-tracking** ブランチです。
2. Unity Hubの「追加／ディスクからプロジェクトを追加」で **このフォルダー** を選びます。
3. 対象環境は **Unity 2020.3.6f1 / Built-in Render Pipeline** です。この環境のAPIでC#コンパイルを確認しています。
   別のUnityを使う場合はこのフォルダーをコピーして開いてください。URP/HDRPへの変換は不要です。
4. `Assets/Scenes/Simulation.unity` を開き、上部の **Play** を押します。
   シーンを見つけにくい場合はメニュー **Parallax > Open Simulation** でも開けます。
5. Gameビューは **1440×960** または同じ縦横比にすると読みやすくなります。UIはウィンドウサイズに合わせて縮小します。

Python・RealSense・EyeTracker-RS・Arduinoは起動不要です。初期版はスライダーで左右の視点を動かします。
画面表示は英語ですが、操作の意味は以下にまとめています。

## 操作

| 表示・操作 | 内容 |
|---|---|
| Tracking ON / h | 視点スライダーの値を光路計算に反映。OFFでは最後の視点位置を保持します。実機ProjectPBのhとは独立したシミュレーション操作です。 |
| Head X / Y | 両目の中点の左右・上下位置。単位mm。 |
| Eye distance from LCD | 液晶表示面から目までの距離。初期値600mmはシミュレーション用の仮定です。 |
| Eye separation | 眼間距離。初期値64mmは仮定です。 |
| Head yaw | 両目の奥行き差を作り、左右を別々の3D位置として計算します。顔認識ではありません。 |
| Lens to image / LCD | レンズから照射像／液晶表示面までの距離。差が光路計算に使う距離gです。 |
| Source period / width | 照射像の水平方向の周期／幅。幅は一様な発光帯として扱います。 |
| Raw shift per LED column | LED列が1つ進んだときの像の移動量。周期を引く前の値を入力します。 |
| Phase-0 source offset | 位相0の線群全体の初期位置。液晶中心での斜め座標のオフセットです。 |
| Invert image shift | LEDの列移動に対して像を逆向きに移動。初期設定はONです。 |
| 0 / 1 / 2 / 3 | 点灯位相を固定。 |
| Animate phases slowly | 毎秒2位相の低速表示。120Hzのハードウェア同期を再現する機能ではありません。 |
| Show exclusive coverage | 4位相を通して、各サブピクセルが左右それぞれに単独で届く機会を持つか表示。 |
| Detail / Full LCD | 24mm幅の拡大／液晶全体。全体表示では縮小による模様の折り返しが生じます。定量判定にはScanを使います。 |
| Separate planes in 3D | 図だけ面間距離を拡大して光路を見やすくします。数値計算には影響しません。 |
| Scan all ... RGB centres | 1920×1080×3＝6,220,800点を4位相分検査。バックグラウンドで実行します。 |
| Export ... | 現在の領域図PNG・設定JSON、最後に完了した検査CSV・その検査時の設定JSONを保存。 |
| Save / Load settings | 設定JSONの保存／読み込み。パネル寸法などUIにない値もJSONから変更できます。 |

### 色の意味

1位相の表示：**緑＝左目だけ、青＝右目だけ、ピンク＝両目へ到達、暗色＝どちらにも届かない**。

4位相の表示：**緑＝左だけに単独提示の機会あり、青＝右だけにあり、白＝左右とも別々に単独提示の機会あり、暗色＝どちらにもなし**。
同じ位相の両眼への重なりを、正しいステレオ提示として数えません。

3D図は白が液晶、オレンジが照射像、灰色がレンズ面、緑・青の十字が左右の視点です。
見やすさのため線群から代表線だけを表示します。すべての発光線を3Dオブジェクト化していません。

## 初期寸法

| 項目 | 値 |
|---|---:|
| レンズ→液晶表示面 | 6.5mm |
| レンズ→照射像面（理論値） | 6.359mm |
| 照射像→液晶表示面 g | 0.141mm |
| 像の水平周期 | 0.76928mm |
| 像の水平幅 | 0.1272mm |
| LED列ごとの生の像移動 | 0.96227mm |
| 斜め線 | 観察者から見て「＼」、横：縦＝1：3 |
| LEDの順序 | 左から0→1→2→3、像移動は結像反転を仮定 |
| パネル寸法（既存コードの値） | 528×297mm、1920×1080、RGB横配列を仮定 |
| 視点（初期仮定） | 液晶前600mm、眼間距離64mm、中心正面 |

像の幅は水平幅と解釈しています。もし0.1272mmが線に垂直な幅なら、水平幅へ換算して入力してください。
パネルの画素ピッチは幅÷画素数から計算します。既存コードに別途存在する0.27mm固定値は混用していません。
位相0の絶対位置とカメラ座標変換はまだ実機校正していません。

## 計算式と仮定

液晶中心が原点、右がx、上がy、観察者側がzです。照射像面はz=-g、目はE=(xe,ye,Ze)です。
モデル上の左目はxが小さい側、右目は大きい側と定義しています。将来カメラ入力を追加するときは、人物の左右ラベル・カメラ軸との対応を明示的に変換します。

像の斜め座標は `s = xs + slope * ys`、`slope = 1/3`。
位相kの線の中心は `sourceOffset + phaseDirection*k*rawPhaseStep + n*sourcePeriod`。

液晶上の点P=(x,y,0)から目へ向かう直線を像面まで戻すと、

```text
sourceCoordinate = (1 + g/Ze)*(x + slope*y) - (g/Ze)*(xe + slope*ye)
```

この値と最寄りの発光線中心との距離が像幅の半分以内なら、その目に届くと判定します。
上下移動、横移動、奥行きの周期補正はこの式に含まれます。従来のhaba補正は重ねていません。

**像面から先は直進、面は平行、発光帯は一様、角度方向の発光制限はない**という理想モデルです。
実機のレンズによる出射角制限、像のボケ、回折、瞳径、画素開口率、液晶ガラス内の屈折、液晶応答時間、LEDと表示の同期ずれは含みません。
したがって物理的なクロストーク率や、実際にフル解像度で見えることを保証するシミュレーターではありません。

### フル解像度の検査

4位相のそれぞれで、RGBサブピクセルの**中心**が左だけ／右だけへ届くか数えます。
各サブピクセルに左右それぞれの単独提示スロットがあることを必要条件とし、RGBすべてが条件を満たす画素も数えます。
画素を半分ずつ固定分割して解像度が保たれるとみなす方法ではありません。
ただし中心が通っても有限の開口全体が通るとは限らず、明るさの均一性や動画の時間解像度も別途評価が必要です。
検査中は視点を固定したスナップショットを使います。設定変更後は `PARAMETERS CHANGED` と表示され、再検査が必要です。

初期設定の実計算結果は `Validation/default-coverage.csv` と `Validation/RESULTS.md` にあります。
このモデルでは左右の到達領域が大きく重なり、フル解像度の必要条件を満たしません。
実機で分離できている場合は、設定した有効距離・像幅・位相だけでなく、無視した角度分布などのモデル仮定も検討してください。

## 保存先

Windowsでは通常 `%USERPROFILE%/AppData/LocalLow/ParallaxResearch/Parallax Optical Simulator/Results`。
画面にも保存先を表示します。プレビュー設定と検査設定は別々に保存するため、古い検査結果を新しい設定の結果と取り違えません。

## 検証とビルド

- `Parallax > Run Model Checks`：交点計算、逆投影、周期の負値、位相反転、幅境界、重なる視点、理想的な全画素提示ケース、キャンセル、不正寸法を検査。
- `Parallax > Build Windows Simulator`：Windows用exeを `Builds/Windows` に出力。
- exeを別PCへ渡す場合は `Builds/Windows` フォルダー全体を渡します。
- `Validation/Run-ModelChecks.ps1`：Unityを起動せず、.NET SDK 10で同じ計算コードを検査。

作成環境ではUnity 2020.3.6f1の参照DLLとC#コンパイラーで全C#ファイルのコンパイルに成功しました。
計算テストとフル画面のRGB中心検査も成功しています。
2つのシェーダーの頂点・ピクセル処理は、Unity付属インクルードを使用したDirect3D HLSLの単体コンパイルを通過しています。
