# Unity 実機出力モード

Unity **6000.6.4f1** / Built-in Render Pipeline / Windows x64。作業ブランチは `realsense-ray-tracking`、プロジェクトは `UnitySimulation` です。元の `realsense` ブランチのProjectPBは変更しません。

## 起動と最初の確認

1. Unity Hubでこのフォルダーを開き、`Assets/Scenes/Simulation.unity` を開きます。
2. メニュー **Parallax > Build Windows Hardware App** でビルドします。出力は `Builds/Windows/ParallaxHardware.exe`。別PCには **Windowsフォルダー全体**をコピーします（exe単体では不可）。指定UnityのWindows Build Supportが必要です。
3. 対象液晶をWindowsのメインディスプレイにし、1920×1080、希望する60/120/144 Hzを設定します。ディスプレイ側も等倍表示にします。HDRや画質補正によるRGBの変更は、まず無効にして確認してください。
4. exeは1920×1080の排他的全画面・位相0で起動します。Arduinoには自動接続しません。**F1**で設定画面に戻ります。起動引数 `--simulator` を付けると設定・シミュレーション画面から開始します。
5. IMAGE TESTでこれまで確認していた割当方式・レンズ条件・左右画像を指定します。元の周期補正は **ProjectPB: still shader**、レンズから逆算する方式は **Geometric allocation** です。
6. ArduinoのCOM番号を入力し **Connect Arduino**。115200 baud / 8N1、起動待ち2秒後に **ENTER FULLSCREEN LCD OUTPUT**。まずq/w/e/rで各位相を固定し、左白・右黒、その逆で左右の見え方を確認してください。
7. 固定位相を確認後、**t**で4位相連続表示。再度tで現在の表示位相を保持します。F1はLEDを消灯して設定へ、Escは消灯して終了します。

Unity EditorのGameビューは縮小されるため等倍検証には使用せず、ビルドしたexeで確認します。解像度が1920×1080でない、または全画面でない場合、実機画像を黒にして時分割送信を停止します。F1から状態を確認できます。

## 出力内容

- 観察画像や4位相平均ではなく、**その位相のLCD DRIVE**だけを全画面にコピーします。
- 1920×1080の各画素・RGBサブピクセルで計算。左右画像を画面の半分ずつに縮めません。
- 実機モードでは縮小プレビューや観察画像の再描画を省き、MSAA・動的解像度・画面上のUIを使いません。受光プレビューのGainは出力に掛かりません。
- 60 Hzなら理想上15サイクル/秒、120 Hzなら30サイクル/秒、144 Hzなら36サイクル/秒です。初期要求値は144 Hzです。設定はリフレッシュレートの要求値であり、実際のHzや処理速度を保証するものではありません。
- 画像・光学条件・COM・割当方式などは **Save hardware / optical settings** で保存し、次の起動で復元します。保存先は `Application.persistentDataPath/hardware-settings.json`。接続・点灯・追跡ON状態は復元しません。

## 元ProjectPBから移した操作

| キー（実機出力中） | 動作 |
|---|---|
| t | 4位相開始 / 現在表示中の位相で停止 |
| q / w / e / r | 停止中に位相0 / 1 / 2 / 3を選択 |
| k | 停止中に次の位相 |
| h | 眼位置を較正して追跡開始 / 最後の眼位置で固定 |
| o | 周期補正方式のSHIFTを進める |
| [ / ] | 周期補正間隔habaを増減 |
| f / Shift+F | 周期補正方式の傾きslantYを−0.02 / ＋0.02 |
| j / Shift+J | 横追跡ゲインを−0.1 / ＋0.1 |
| Shift+R | 左右入力の交換（内蔵診断画像も対象） |
| 0〜7 | 元画像001〜008の左右PPMペアを読み込む |
| F1 / Esc | 消灯して設定へ / 消灯して終了 |

元画像はexeの隣の `images/IDW/001l.ppm` と `001r.ppm` などに置きます。フォルダーは設定画面から変更できます。P6・maxval 255のPPMに対応し、PNG/JPGは左右のパスから読み込めます。入力が1920×1080なら入力画像も等倍です。他サイズの入力は液晶サイズへリサンプルします。

移植した基本機能は静止画・位相制御・周期補正・眼位置追跡・Arduino通信です。元の動画再生、実験用アナグリフ切替、色補正はこの版に移植していません。h OFFは元C++の初期位置リセットではなく、Unity側の比較操作に合わせて最終位置を保持します。

## RealSense追跡

**EyeTracker-RS.exeは別途起動**します。UnityからD435を直接開く処理はありません。PythonサーバーはUnity側には不要です。元ProjectPBなど、同じUDPポートを使うアプリは終了します。

設定画面の **Start OSC receiver / localhost:8000** を押し、EyeTracker-RSから `/eye/left`、`/eye/right` の `,fff`（メートル）を送信します。右と左の順番には依存せず、100 ms以内の新しい左右ペアを採用します。1秒以上更新されなければ最終位置を保持します。設定画面でlive/staleを確認できます。

1. カメラを固定し、手動Head X/Y/Zを、較正時に実測した液晶中心から顔中心までのmm値に合わせます。
2. その位置でhを押します。以降の移動を較正位置からの差として反映します。
3. 頭を右・左・前後に動かし、向きと距離の変化を確認します。逆ならCamera X directionを変更し、再較正します。Camera tiltは初期8度、Y方向の初期符号は−1です。設置角度に合わせて変更してください。

幾何方式は受信した左右眼のXYZをそれぞれ保存し、奥行き・高さの違いも扱います。周期方式は元コードの `haba = 330 + int((Zref-Z)/2)` と横補正式を移植し、元コードの左向きXをUnityの右向きXへ変換しています。横式の初期値はゲイン0.7、カメラZオフセット110 mm、分母の距離定数324.5 mm、サブピクセル換算0.09 mmです。これらは元実機向けの経験式で、幾何方式の液晶ピッチとは別です。原式の特異点付近では横補正を更新しません。新しい設置で自動較正された値ではありません。

## Arduinoと液晶のタイミング

元ProjectPBと同じ単一バイナリバイトを使います。ASCII数字や改行は送りません。

| 状態 | 送信値 |
|---|---|
| 時分割開始 | 20（同期リセット）、12（開始） |
| そのフレームの描画後 | 200 + 表示位相、次の位相へ進む |
| 固定フレーム描画後 | 210 + 表示位相 |
| 設定画面・フォーカス喪失・終了 | 13（停止）、110（消灯） |

フレーム終了時に、描画した位相と同じ番号を送ります。ただしUnityの `WaitForEndOfFrame` は**液晶パネルの実表示完了通知ではありません**。Windows・GPU・USB・液晶応答の遅延は残ります。ArduinoからのACKや光学センサーによる閉ループ同期も未実装です。元ファームウェアがこのコマンド表に対応していることを確認し、固定位相が正しい状態から、連続表示時の位相順序・遅延を実機で調べてください。4位相の物理的な同期とクロストーク改善を検証済みとはしていません。

## 検証範囲

OSCデコード、UDP左右ペアの確定・期限切れ、PPMの上下方向・バイナリ画素、左右眼の独立XYZ、既存光学モデルのCPUテストを用意しています。C#は利用可能なUnity参照DLLで構文検査し、シェーダーはD3D HLSLで単体検査します。この作業環境にはUnity 6000.6.4f1がないため、そのEditorでのWindowsビルド・GPU表示・COM接続・実機同期は未検証です。

## GitHubへの反映範囲（2026-10-14）

2026-10-13にこの作業で作成した実機出力版を反映し、144 Hzの選択・保存に対応。焦点距離はradius/(n-1)=約1.0204 mm、有限距離のLED結像位置は約1.0273 mmを維持します。これは設定値に基づく計算で、焦点の実測・メーカー保証ではありません。
