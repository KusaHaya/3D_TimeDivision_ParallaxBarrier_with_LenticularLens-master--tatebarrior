# 距離による周期補正の候補式（現行方式は維持）

この追加ではmain.cpp、interleave.frag、sbs_interleave.fragを変更しない。現行の線形補正と描画・点灯タイミングはそのまま残す。BarrierPeriodModel.hは独立した候補関数であり、includeや実行経路への組み込みもまだ行わない。

## 仮定と単位

L：液晶表示面から観察者までの距離 [mm]。カメラ座標のZをそのまま使うのではなく、液晶表示面を基準に校正する。
g：スクリーン〜液晶の実効間隔 [mm]。アクリル5 mm、n=1.49、背面ガラスを仮に1 mm、n=1.5とすればg=5/1.49+1/1.5 ≈4.022371 mm。
Pb：スクリーンでの同位相の縞の水平中心間隔 [mm]。0.7434 mmは中央のモデルからの概算で、実機全域の確定値ではない。
P0：補正前の表示周期。RGB1画素の水平ピッチpならP0=8p/3。

平行面・近軸屈折・同じ局所周期の仮定で、必要周期P(L)=Pb L/(L+g)。現行の挿入側では平均周期P=P0/(1-1/h)である。

## 寸法から求める式

h(L)=Pb L / ((Pb-P0)L-P0g)

必要周期がP0より長い挿入側だけで使う。必要周期が短い場合、負のhabaを現行シェーダーへ渡して除去を実現することはできない。候補関数は適用範囲外としてfalseを返し、出力値を変更しない。現行範囲2〜100000を超える場合も同様。

## 実機の基準合わせを残す式

基準距離L0で合わせた値h0を使い、

h(L)=1 / [1-(1-1/h0)(1+g/L)/(1+g/L0)]

とする。これはL=L0で必ずh=h0になる。Pb/P0を基準合わせから逆算する式で、画素ピッチやPbを未確定のまま勝手に置き換えない。

ただし、基準合わせによる値が「周期の調整」以外の誤差を吸収している場合や、距離ごとに局所周期が変わる場合には、この一つの式では一致しない可能性がある。画面全域での正しさを保証する式ではない。

## 線形近似との比較

現行コード（距離がmmなら）：h_old(L)=h0-0.5(L-L0)。実際のC++では整数への切り捨ても含まれる。

候補曲線の基準点での接線：

h_linear(L)=h0+k(L-L0)
k=-h0(h0-1)g/[L0(L0+g)]

例としてL0=1000 mm、h0=330、g≈4.022371 mmならk≈-0.435。これは例であり、実測した基準距離・habaの代わりに採用しない。

## 後日の実機比較

1. 同じ観察位置・基準距離でh0と位相を合わせ、保存する。
2. 現行線形式と候補曲線を同じ基準点から比較する。
3. 800/1000/1200 mmなどで、画面中央と端の位置ずれ、左右クロストーク、観察範囲を測る。
4. 位相・傾き・LED点灯タイミングの条件を共通にする。

関数は小数habaを返す。現在のmain.cppはintのhabaを使うため、将来組み込む際は整数化の方法を明示してそろえるか、小数を保持してシェーダーへ渡す方式を別に比較する。丸め閾値や整数化による局所誤差は、上の平均周期の式では完全には表さない。
